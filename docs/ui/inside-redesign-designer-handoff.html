1. Visual thesis and constraints

A quiet execution ledger where status is read first, evidence unfolds in place, and every claim has a visible source.

Preserve Karst's injected design system, semantic controls, VS Code theme variables, sentence-case copy, status ramp, keyboard focus, and reduced motion. No new UI framework, component library, palette, or parallel business-rule layer.

  • Missing history is absence, never zero, pass, or reconstructed prose.
  • AI prose never determines a stage verdict.
  • Unknown PR state is unmerged; Done requires every current PR to be literally merged.
  • Unsupported token usage is omitted, never shown as zero.
  • Process identity is what was captured when it ran, not current Settings.

7. Responsive and accessibility requirements

Normal width

  • All six stage labels visible.
  • Status/name first; identity and token metadata secondary.
  • Expanded evidence uses available repository/file context.

300–430px

  • Move identity and token metadata to a second line.
  • Wrap PR branch/title content.
  • Keep timeline node and edge aligned.
  • No whole-component horizontal scrolling.

Keyboard

  • Disclosures are native or have complete keyboard semantics.
  • Actions are real buttons/links with visible focus.
  • Disabled controls explain why they are unavailable.

Motion

  • Reduced motion removes spinner animation.
  • Visible running state remains present.
  • Async labels remain stable while pending.

9. Handoff checklist

  • Provide desktop and 300/360/430px versions of the complete Inside block.
  • Provide collapsed/expanded variants for every process and all seven statuses.
  • Provide Settings assignment rows in valid, disabled, missing-profile, provider-error, and model-error states.
  • Annotate token usage, focus, disclosure, async pending, unknown-result, and reduced-motion behavior.
  • Show bounded repository, findings, and gate continuation patterns.
  • Identify any genuinely new design-system primitive or token; do not introduce screen-local visual values.
  • Keep the webview presentation-only: no business-rule derivation, URL parsing, path construction, or status aggregation in the UI.
