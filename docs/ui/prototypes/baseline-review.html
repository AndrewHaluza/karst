Baseline review — mockup

Surface: the "Review baselines" blocker (BaselineReview.tsx in BlockedBanner). Today it renders every changed screenshot at full size inside the red strip of the stepper card. On this machine the last tickets had 55–190 changed entries (globalStorage/baseline-review: 110–380 files).

Revision 2 (after the subagent review). A rev tag marks each change. D537 holds the same rules in its "REVIEW REVISIONS" section.

R0 · Problems now

  1. One long page. Each entry puts a full-size image, a 3-way switch and the buttons in the card. 48 entries ≈ 48 screen heights of scroll under the stepper. Inside and the shelf move far down.
  2. Wrong tone. The review sits in the red .fault strip. A baseline review is a "needs you" decision (amber in the rail and sidebar, @arch:BASELINE-REVIEW), not a failure.
  3. No grouping. One screenshot in 5 themes gives 5 separate rows. You read the same page 5 times.
  4. Text marks, not glyphs. "○ Needs review", "✓ Approved" are characters, not the glyph set that Inside and the rail use.
  5. No navigation. No filter (approved rows stay in the list), no next / previous, no keyboard keys. A reject form opens in the middle of the long list.
  6. The image does not fit. A tall full-page screenshot is wider and taller than the card. The Difference view is black with no help to find the change.
  7. No visual variant. tests/visual/variants.ts has no baseline-review state. Nobody saw this surface in a screenshot.
