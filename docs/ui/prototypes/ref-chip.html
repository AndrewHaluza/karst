A · One verb pair, one chip on every surface

All surfaces use one chip and one pair of words: Waits on (incoming) and Unblocks (outgoing). A cycle uses Cycle with. The ticket form keeps Parent and Child. "Blocked by" and "needs" go away. The GUI uses sentence case. The CLI uses lower case.

The chip keeps the pill form. The border and the wash use the rail stage color, and the chip has no status mark. The id and the uppercase stage word use a text tone of the same stage hue (--stage-<key>-fg), darker in light themes and lighter in dark themes, so the text reaches 4.5:1. A dense row shows one chip and a +N button. The button opens the other chips in a list below the row.

State rules (the same order as the rail)

  • Needs you wins over the stage: the attention border (--k-attention), the rail 30% needs wash, and the pause mark. This is the only chip with a mark: it asks the reader to act, and the amber border alone is below 3:1 in light themes.
  • In progress (scope … ship): the stage border, the 20% wash and the stage word. Scope uses the rail scope fill pair.
  • Done: the done green and the word DONE. Closed: the closed gray and the word CLOSED.
  • Draft: a dashed outline and the word DRAFT. The accessible name is "D497, draft pending", as ticketRefView gives it.
  • Missing: a dashed outline, muted text, the word MISSING, and no link.
  • Cycle: the red verb with the cycle icon, and a red chip border.
  • Raised priority: the priority chip gets an up arrow. The row name keeps the fact "raised to high because D498 waits on it".
