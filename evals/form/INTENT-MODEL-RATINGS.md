# Ticket-Form Intent Pass: Model Ratings & Evaluation Benchmark

This document tracks model evaluation scores on the ticket-form intent generation pass (`generateIntent` in `src/workflow/classify/intent.ts`). It evaluates the test charter and acceptance criteria generated by models against real ground-truth `FAIL_TO_PASS` test suites from pinned TypeScript issues in `evals/instances/multi-swe-bench-ts-v1.jsonl`.

Each model is evaluated across two modes to measure the downstream effectiveness of the ticket improver:
* **`raw`**: Intent generated directly from the author's untreated issue description.
* **`improved:builtin`**: Intent generated from the description after running the built-in `improveDescription` pass.

## 3. Core Insights & Benchmark Findings

### Downstream Proof of Prompt Improver
The benchmark confirms that running the prompt auto-improver (`improveDescription`) before intent generation directly boosts downstream charter quality:
* On **Flash Medium**: F2P test coverage climbed from **45.8% to 60.0%** (+14.2%).
* On **Flash Low**: F2P test coverage climbed from **50.0% to 58.3%** (+8.3%).
* The improver strips issue template boilerplate, clarifies reproduction steps, and unblocks models that are otherwise overly cautious on ambiguous issue bodies.

### The 83.3% Task Pass Rate vs. Aggregate Test Coverage
While aggregate test coverage sits between 58% and 60%, **5 out of 6 tasks achieved 100% test coverage**. The aggregate gap comes entirely from a single task (`darkreader:pr-6747`):
* The issue author reported high-level site styling failure on Unix Stack Exchange.
* The model correctly authored user-observable acceptance criteria (*"Given Dark Reader is active, when visiting Unix Stack Exchange, site fixes are applied"*).
* However, all 5 ground-truth tests in the PR were internal unit tests in `parse.tests.ts` asserting internal array indexing (`fixes[0]` vs `fixes[fixes.length - 1]`).
* The model appropriately avoided leaking internal implementation details, which caused the judge to mark the low-level parser assertions as missing.

### Guardrail Adherence
Across the runs in the leaderboard:
* **0 Test Leaks**: Ground-truth patch filenames and test identifiers never leaked into generated charters.
* **0 Degraded Parses**: 100% first-attempt JSON/schema parsing without fallback retries.
* **Unsupported scenarios**: 0.00 for both Gemini rows, and 0.83 for the Haiku row.

## 4. How to Backfill & Run New Models

To backfill this benchmark for other models (Claude, Codex, OpenCode):

```bash
npm run eval:form -- --pass intent \
  --provider <claude|antigravity|codex|opencode|opencode2> \
  --model <model-id> \
  --judge-model <judge-model-id> \
  --source raw \
  --source improved \
  --only vuejs/core:pr-8470,vuejs/core:pr-8785,mui/material-ui:pr-23778,mui/material-ui:pr-23786,darkreader/darkreader:pr-7241,darkreader/darkreader:pr-6747 \
  --runs 1
```

Preserve results by copying the generated folder from `eval-results/form-<timestamp>/` to `evals/form/references/` and appending the row to the leaderboard table above.
