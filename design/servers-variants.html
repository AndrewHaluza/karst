Servers panel — approved design

One line per service: status dot, name, address, and the actions that belong to each. Panel-level Start / Restart / Stop live in the header so they work in every state, including the ones with no rows. What this design commits to

  • One line per service, at every width. Narrow compacts (padding, font, and the address collapsing to :5173) instead of restacking into blocks — measured at 300px with zero horizontal overflow.
  • Status is the dot. No repeated word in the row. Filled disc = running, hollow ring = offline; the dot is role="img" with aria-label + title, and the address column reads — when offline. Never color alone.
  • Actions are two groups. Open and Copy act on the address and are dead without it, so they ride with the value. Restart and Stop act on the process and stay right, after a wider gap. Offline rows get Start, not Restart — a stopped process has nothing to cycle.
  • Panel-level Start / Restart / Stop in the header. They act on every service at once and stay reachable when the body has no rows to hang a button off. Each disables itself when it would be a no-op, and says why on hover.
  • Icons, not labels, in rows. Inline SVG — no icon font, no external asset, because the webview CSP forbids both. Resting color off the status ramp: Open blue, Copy purple, Restart yellow, Stop red, Start green. Hover is a separate channel (surface + border + the glyph scaling), so color means which action and hover means you are on it. Every button keeps its word in aria-label + title.
  • Keyboard. Every action is a real <button> in DOM order with the theme's focus ring at a 23px target; the row highlights on :focus-within.
  • No new framework. Plain template strings, the existing --vscode-*/--st-* tokens, and the existing .panel/.phead/.pbody shell — exactly like src/ui/dashboard/webview.html today.

Needs from the host before this can ship

  • DashboardState.serversPhase ('ready' | 'loading' | 'error') and serversError?: string — the loading and error states have no source today; they are mocked here.
  • Two new webview messages beside the existing spin-servers: restart-servers and stop-servers (panel-level Restart / Stop), plus retry-servers for the error state. Row-level open-server / copy-server-url / restart-server / stop-server are unchanged.
  • Everything else already ships in ServerView[] + hasRunnableRepos.

Known costs

  • Four unlabeled icons per row lean on tooltips — learnable, but not self-describing on first visit. At 14 rows the repeated blue/purple/yellow/red column is the loudest thing in the panel.
  • Dropping the status word buys the density but spends the one label that never needed a hover.
  • At 300px the service name ellipsises; the full name stays in its title.
